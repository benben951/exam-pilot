# 大模型考研与个人知识库先验研究

> 扫描日期：2026-08-23
> 目标：吸收可复用机制，不把第三方项目的宣传功能当作已验证的学习效果。

## 结论

现成项目主要分成三类：

1. AI错题本：识题、标签、解析、相似题、掌握度统计。
2. LLM编译知识库：Raw、Wiki、查询、回流、Lint和间隔复习。
3. 学习规划器：日程、任务、进度和提醒，但通常缺少考试测评证据。

没有发现一个现成开源项目同时解决：北大软微金科的数学二、英语一、831、政治、在职约束、来源审计和录取概率。因此不应直接换成某个仓库，而应提取模块。

## 重点来源

### wttwins/wrong-notebook

- 链接：https://github.com/wttwins/wrong-notebook
- 证据：公开仓库，约680 stars、238 commits；README描述了AI识题、知识点标签、相似练习、掌握状态筛选、打印导出和学习统计。
- 可复用：错题记录应同时保存题面、错误类型、知识点、掌握状态、复习队列和相似题生成请求；按科目建立独立错题本。
- 不直接复制：它是通用学生错题应用，不能替代831模型卡、数学知能行等级或留出测评；仓库的默认管理员配置也不应原样用于生产环境。

### black-zero358/GradNote

- 链接：https://github.com/black-zero358/GradNote
- 证据：公开项目，FastAPI + LLM，定位为错题知识点管理和知识图谱。
- 可复用：把“错题 -> 知识点 -> 关系 -> 学习建议”拆成结构化后端对象，而不是只保存一段AI解释。
- 不直接复制：公开证据较少，项目规模小；知识图谱关系必须经过题目和教材来源校验，不能把模型自动抽取当成真知识。

### arturseo-geo/llm-knowledge-base

- 链接：https://github.com/arturseo-geo/llm-knowledge-base
- 证据：公开schema项目，README提供AGENTS规范、Raw/Wiki/output/learning目录、概念索引、图谱、FSRS式复习队列、知识缺口、Socratic问答、污染隔离和Lint规则。
- 可复用：把Wiki编译和学习层分开；把临时输出放在sandbox，只有通过来源、冲突和适用范围检查后才Promote到Wiki；为每个概念自动生成卡片和复习任务。
- 不直接复制：其“LLM编译后不人工编辑Wiki”不适合你的高风险考试结论；招生政策、考试科目和录取规则必须保留人工确认和官方来源门槛。

### Karpathy llm-wiki gist

- 链接：https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f
- 可复用：LLM负责整理、交叉引用和维护，Markdown文件作为透明持久层；适合解释我们为什么不先上向量RAG。
- 边界：它是通用个人知识工作流，不提供考研能力测量、错题诊断或录取预测。

## 我们的差异化

```text
Raw证据
→ 科目Wiki/模型卡/错题规则
→ 闭卷复测和首次留出测评
→ 月度能力基线
→ 录取风险与概率
```

核心差异不是“有一个AI聊天框”，而是：

- 每条长期结论都有来源等级和复核日期。
- 学习建议必须落到可验收任务。
- 训练正确率和正式留出测评严格分离。
- 831用模型卡和闭卷输出衡量，数学保留知能行进度，英语按题型诊断，政治按时政/选择题/主观题分层。
- 概率模型拒绝用学习时长、经验贴和平台分数直接编造录取概率。

## 不引入的功能

- 不为了“知识图谱”盲目增加图数据库。
- 不把所有PDF全文一次性喂给大模型。
- 不自动把模型总结写入Wiki。
- 不把单个上岸经验贴当作普遍规律。
- 不把AI生成相似题当作正式测评题。

## 下一步最小改造

1. 为错题和模型卡补来源、掌握状态、错误类型、下次复习日期。
2. 增加sandbox/output目录，查询结果默认不回流。
3. 增加Promote记录和Lint检查：来源缺失、重复、冲突、过期政策、孤立节点。
4. 把三份北大软微经验合集按文章切分，先生成索引，再按数学/英语/831/政治/复试提炼，不复制大段原文。
5. 每月只把首次、严格限时、留出的整科测评送入录取预测。

## 关于此前公众号/文章

此前讨论的“用大模型和大数据帮助考北大”的思路，与Karpathy式LLM Wiki和截图中的三层知识库逻辑高度相似。当前可确认的是工作流思想，不应在没有原文链接或作者信息时，把截图中的案例数字或效果当作独立验证结果。
