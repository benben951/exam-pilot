# 北大软微金科录取预测体系

> 目标：用可复核的测评数据预测“当前实力、考试日分数和进入复试概率”，在院校复试参数完成校准后再输出最终录取概率。

## 一、使用边界

这个系统是决策工具，不是录取承诺。它遵循三条硬规则：

1. 学习时长不能直接兑换成分数。
2. 测评数据不足时输出“数据不足，无法判断”，不填默认分数。
3. 复试权重、统考复试人数和实际录取人数没有官方或历史数据支持时，不输出最终录取概率。

院校参数在 [data/admission-target.json](../data/admission-target.json)，测评在 [data/assessment-records.json](../data/assessment-records.json)，生成结果在 [monthly-report/admission-forecast-latest.md](../monthly-report/admission-forecast-latest.md)。

当前配置中的考试日期 `2026-12-20` 只是轨迹计算用的规划假设，不是已确认的 2027 研考官方日期；官方日期发布后必须更新院校参数。

## 二、预测链路

```text
日报实际执行 → 分科测评 → 分数分布 → 总分/单科线模拟 → 进入复试概率
                                         ↓
                              复试参数校准 → 最终录取概率区间
```

### 当前实力

使用最近的可比测评，按测评类型、是否限时和距离预测日加权，输出每科 `P10/P50/P90`。当前只回答“如果现在考试，大约是什么水平”。

### 考试日轨迹

只有每科至少 3 次测评、跨度至少 14 天，并且最近 28 天至少有 7 天真实 `actual_min` 记录时才启用。趋势会限制在配置的月度上限内，不允许线性外推到不现实的分数。

### 初试模拟

对四科分数和复试线不确定性做 20,000 次模拟，同时检查：

- 总分是否超过历史复试线样本；
- 政治、英语、数学、831 是否同时超过单科线。

复试线历史样本越少，院校参数可信度越低。当前只有 2026 一个同口径官方年份，因此系统会计算初试进复试概率，但标记低可信度。

## 三、什么数据可以录入

推荐优先录入以下测评：

| `kind` | 用途 | 是否自动换算为考研分数 |
|---|---|---|
| `target_past_paper` | 软微/目标院校真题 | 是 |
| `full_mock` | 完整限时模拟 | 是 |
| `subject_mock` | 单科限时模拟 | 是 |
| `diagnostic` | 阶段诊断 | 否，只用于找薄弱点 |
| `section` | 阅读、选择题等分块测试 | 否，只用于找薄弱点 |
| `platform` | 知能行、苍盾等平台指标 | 默认不直接计入考试分数 |

命令示例：

```powershell
python .scripts\admission_forecast.py add `
  --date 2026-09-01 --subject math --kind subject_mock `
  --score 108 --max-score 150 --timed --first-attempt --holdout `
  --source "数学二阶段测试"
```

诊断题不是完整试卷时，只用于确定薄弱点，不进入录取概率：

```powershell
python .scripts\admission_forecast.py add `
  --date 2026-08-20 --subject english --kind diagnostic `
  --score 32 --max-score 40 `
  --source "考研英语阅读专项"
```

## 四、日常命令

```powershell
# 检查所有 JSON 和测评记录
python .scripts\admission_forecast.py validate

# 生成预测，默认写入快照和 Obsidian 报告
python .scripts\admission_forecast.py forecast --as-of 2026-09-30

# 只预览，不写文件
python .scripts\admission_forecast.py forecast --as-of 2026-09-30 --no-save
```

推荐在每月末、完成完整模拟后或重大复盘后生成一次快照。快照不会覆盖历史结果，可以观察概率和数据可信度如何变化。

## 五、解读规则

### 防止假精确

- 第一次月度整科/阶段测评应标记 `role: baseline`，只用于诊断，不进入概率。
- 报告同时展示总分线通过率、各科单科线通过率和最低通过率的瓶颈科目。
- 概率应按区间和瓶颈解读，不把单点百分比当作承诺。
- 383分及55/55/90/90仅是2026官方历史参考，2027必须等待官方复试线。

| 输出 | 含义 |
|---|---|
| 今日实力 | 当前测评证据对应的分数分布 |
| 考试日轨迹 | 在执行记录和测评趋势成立时的未来分布 |
| 进复试概率 | 同时满足总分线和四科单科线的模拟比例 |
| 最终录取概率 | 只有复试模型有数据时才出现 |
| 可信度 | 测评数量、执行记录和院校历史样本共同决定 |

不要把 `P50` 当成承诺，也不要只看总分。北大软微金科的单科线，尤其数学和 831，可能比总分更早触发风险。

## 六、需要逐步补齐的校准数据

1. 2022–2027 同口径官方复试线和招生说明。
2. 金融科技方向统考复试名单人数、实际录取人数。
3. 电子信息金融科技方向复试成绩权重和不及格规则。
4. 个人每科限时真题/模拟成绩及考试日误差。
5. 复试模拟：英语、自我介绍、经济学问答、项目问答。

在第 1–4 项没有补齐前，系统只把“进入复试概率”作为主要量化结果；月度健康分只用于判断执行风险，不能当录取概率。

## 七、与现有项目的关系

- `timeline-2026.md`：唯一学习目标源。
- `study-db.json`：日常实际学习和日报数据。
- `zhinenxing-progress.json`：数学模块等级趋势。
- `monthly-review.md`：执行健康分与红线干预。
- 本系统：基于测评和院校参数的分数/概率预测。
